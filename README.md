# Креативный мозг — ReshalaBot

Telegram-бот бесплатного урока и доступа к закрытому каналу. WebApp нет.
Рабочая схема разовой оплаты через ЮKassa сохранена: redirect, RUB, capture=true.
Начальный тариф — 400 ₽ / 30 дней; администратор может менять тарифы из бота.
Оплата проверяется автоматически, затем бот сам присылает ссылку входа.
Автопродление добавлено как отдельная функция и **по умолчанию выключено**.

## Путь пользователя

1. /start: сначала приветствие, затем отдельное сообщение со ссылкой на бесплатный урок.
2. Под уроком — переход к программе. Материал сохраняется в истории.
3. Программа → тарифы с ценами и сроками → условия → разовая оплата.
4. После подтверждения ЮKassa бот сам отправляет приглашение. «Проверить оплату»
   — запасной способ, обязательного нажатия больше нет.
5. По ссылке человек подаёт заявку. Бот проверяет владельца ссылки и действующий
   доступ **до одобрения**. Пересланная ссылка не выдаёт доступ другому аккаунту.
6. /start действующего участника показывает срок, восстановление ссылки,
   продление и активность. Оставшиеся дни сохраняются при продлении.

Выбор цели — добровольная второстепенная кнопка в программе; он не закрывает
путь к уроку или оплате. Приветствие и видео не объединяются в одно сообщение:
preview располагается под текстом урока. Внешний вид preview зависит от Telegram.

Команды покупателя: /start, /help, /support, /paysupport, /terms,
/cancel_subscription. Отмена автопродления сохраняет оплаченный срок.
Если платёж уже передан банку, отмена будущих попыток не отменяет его задним числом.

## Администрирование

/admin открывает кнопки; администратор также видит вход в меню на пользовательских
экранах. Все административные команды, callbacks и ввод проверяют Telegram ID и
доступны только в личном чате. Приоритет переменных: ADMIN_ID → ADMIN_IDS → ADMINS
(первая непустая, списки не объединяются). Пустая конфигурация не открывает доступ.

- **Лид-магнит:** установить любую публичную http/https ссылку, проверить порядок
  сообщений, удалить ссылку. Старые команды /set_intro_video и /clear_intro_video
  остаются aliases. Исторические media settings не удаляются.
- **Тарифы:** до 20 вариантов; название, целая цена 1–1 000 000 ₽, срок 1–3650 дней,
  включение/скрытие. Новый тариф сначала скрыт. Уже выставленные счета сохраняют
  исходные цену и срок. Старые m1_first, m1, m3 продолжают обрабатываться.
- **Тексты:** приветствие, урок, программа, оформление, готовый счёт, вход,
  действующий доступ, продление, окончание, напоминание об уроке. До 2000 единиц
  длины Telegram; эмодзи могут занимать две. Поля {date}/{activity} проверяются;
  есть возврат исходного текста. Финансовые условия добавляются отдельно.
- **Настройки:** автопродление (выключено при первом запуске), мягкое напоминание
  об уроке, напоминание об окончании за 2–14 дней, ID группы, ссылка поддержки,
  ссылка на первый материал/навигацию внутри канала.
- **Выдать / отозвать доступ:** ID и срок для выдачи; ID для отзыва. При проблеме
  удаления участника админ получает ошибку и может повторить операцию.
  Отзыв отключает будущие автоплатежи. Настроенных администраторов бот не исключает.
- **Воронка / статистика:** первые запуски за 7/30 дней или всё время; достигнутые
  этапы и максимальный этап каждого человека; оплаты, выручка, источники,
  сообщения/медиа группы. Причины остановки и просмотры внешнего видео не угадываются.
- **Путь пользователя:** последние 25 событий, источник, активность, автопродление.
- **Проверить подключение:** права приглашения/удаления в канале, доступность группы,
  наличие настройки ключей. Проверка не создаёт платёж и не показывает секреты.

Ссылки, тексты и настройки сохраняются в SQLite, действуют после перезапуска и
не требуют публикации нового кода. Смена условий оферты по тому же URL требует
увеличения OFFER_VERSION в окружении; смена URL также требует нового согласия.

## Оплата и восстановление

Запрос создания счёта и его Idempotence-Key сохраняются **до** обращения к ЮKassa.
Повторный клик, тайм-аут или перезапуск используют тот же запрос. Пока исход
предыдущего платежа неизвестен, новый счёт не создаётся. Это не смена платёжного
провайдера или способа оплаты, а защита повторных попыток существующего API.

При сверке проверяются ID, владелец, проект, назначение, тариф, сохранённый срок,
сумма и RUB. Доступ выдаётся только для succeeded + paid=true.
waiting_for_capture не считается завершённой оплатой.
Срок берётся из сохранённого счёта, а не из текущих цен администратора.

Запись оплаты, продление, события и сохранённое согласие выполняются в одной
транзакции BEGIN IMMEDIATE. Повторная обработка не добавляет второй срок.
Общая SQLite connection сериализована; операции одного пользователя защищены
блокировкой. Запускать **один процесс polling на токен и базу**.

Фоновая сверка запускается каждые 20 секунд, выдача оплаченного доступа —
автоматически, без публичного webhook-сервера. Сетевые ошибки и очередь могут
увеличить задержку. Подтверждённая оплата сохраняется даже при ошибке Telegram;
неудачная доставка повторяется отдельно с паузой 5 минут, без повторного продления.
При неопределённом ответе Telegram возможен повтор сообщения, но не повтор оплаты.
Уже завершённые исторические платежи при миграции повторно не рассылаются.

ЮKassa гарантирует идемпотентность в течение 24 часов:
[документация API](https://yookassa.ru/developers/using-api/interaction-format).
Поэтому неизвестный POST без payment_id старше 23 часов автоматически не повторяется.
Такой редкий случай требует сверки оператором в ЮKassa; нельзя удалять запись
или создавать новый платёж наугад. Счета с известным ID продолжают проверяться GET.

## Автопродление — отдельная опция

Обычные покупки не сохраняют способ оплаты. Существующие участники не подключаются
к автопродлению автоматически. Чтобы предлагать его новым покупателям, администратор
должен отдельно включить опцию в настройках; покупатель затем выбирает явную кнопку
с согласием на цену, срок и повторное списание.

Две предварительные оплаты не требуются: способ можно сохранить при первой
успешной покупке. Доступность зависит от магазина и способа оплаты; требуется
payment_method.saved=true. Без подтверждения сохранения автопродление не включается.
[ЮKassa: подключение автоплатежей](https://yookassa.ru/docs/support/payments/extra/autopayment),
[оплата сохранённым способом](https://yookassa.ru/developers/payment-acceptance/scenario-extensions/recurring-payments/pay-with-saved).

- Опция доступна для тарифов от 3 дней. Сохраняются цена, срок и согласие покупателя.
- За настроенное число дней до окончания приходит предупреждение с ценой,
  сроком и отменой. Попытка списания — за сутки до окончания и не раньше 12 часов
  после подтверждённой отправки предупреждения.
- На один период допускается один счёт. Ручной или неизвестный платёж блокирует
  новое автоматическое списание.
- Подтверждённый отказ останавливает автоматические попытки и даёт кнопку ручного
  продления. Тайм-аут сначала сверяется: он не означает отказ банка.
- Изменение цены/срока или скрытие тарифа приостанавливает продление до нового выбора.
- /cancel_subscription доступна в любое время. Поздний ответ первого платежа
  не может снова включить уже отменённое согласие.
- При недоставленном предупреждении списания нет. Просроченные пропущенные периоды
  не догоняются серией списаний. После окончания доступа автопродление отключается.

Подключение рекуррентных платежей конкретного магазина в этом аудите не проверялось.
Чеки, договор магазина, возвраты и споры обслуживаются в существующей настройке
ЮKassa. Возврат в кабинете не вызывает автоматического отзыва доступа: администратор
должен отдельно использовать «Отозвать доступ». Автоматизация возвратов не добавлялась.

## Доступ, группа и напоминания

Приглашение действует час, использует creates_join_request. Боту нужны права
can_invite_users и can_restrict_members. На вход проверяются пользователь, срок
подписки и ссылка; после одобрения ссылка отзывается. Если настроена ссылка первого
урока, новому участнику приходит короткий следующий шаг.

Старые ссылки прежнего формата обрабатываются обработчиком вступления.
После окончания и ручного отзыва открытые ссылки отзываются, участник блокируется;
перед новым подтверждённым доступом снимается блокировка. При ошибке прав
истечение повторяется; покупателю не сообщается об успешном удалении до результата.
Перед истечением сверяются начатые платежи. Неизвестному исходу даётся максимум
24 часа отсрочки, затем доступ закрывается. Поздний подтверждённый платёж
обрабатывается и восстанавливает оплаченный срок.

Учёт активности работает только в указанной группе для действующих участников:
сообщения и сообщения с файлами/медиа. Повторное событие не увеличивает счётчик;
редактирования, сообщения ботов и анонимных отправителей не учитываются.
Содержимое сообщений, имена файлов и файлы не сохраняются. Один медиапост считается
одним сообщением с медиа. Фотоальбом может состоять из нескольких сообщений.
Telegram не даёт боту историю сообщений до подключения.
Для получения всех новых сообщений добавьте бота администратором группы либо
настройте режим приватности в BotFather.
[Ограничения Bot API](https://core.telegram.org/bots/api).

Персональное напоминание использует только ненулевые счётчики за последние 30 дней.
«Разборы» автоматически не распознаются. Через 22–24 часа после первой отправки
лид-магнита возможна одна мягкая попытка напоминания: без оплаты/активного доступа,
без неизвестных счетов и при отсутствии отказа от таких сообщений.
Эту рассылку можно отключить в админке; пользователь может отключить её своей кнопкой.
При неопределённой доставке маркетинговое сообщение повторно не отправляется.

Источники: https://t.me/BOT_USERNAME?start=instagram_creative и аналогичные
параметры из латинских букв, цифр, _ и - (до 64 символов).
Воронка группирует по **первому** запуску, повторные старты не создают новых людей.
Ссылка урока означает отправку, а не просмотр видео.

## Запуск, база и проверки

Python 3.10+; локальные проверки: Python 3.12, python-telegram-bot 21.11.1,
aiosqlite 0.21.0, httpx 0.28.1, python-dotenv 1.2.2.
Существующий список зависимостей сохранён. Команды:

    python -m pip install -r requirements.txt
    python bot.py

Заполните прежнее окружение по .env.example; не заменяйте рабочие ключи тестовыми.
DB_PATH должен указывать на прежний постоянный SQLite-файл. Относительный путь
отсчитывается от рабочего каталога процесса; без переменной используется
credits.db рядом с db.py. Настройки в базе имеют приоритет над начальным заполнением env.
Не запускайте два процесса бота одновременно.

Миграция добавляет таблицы тарифов, запросов платежей, согласий, доставки,
активности и аудита настроек; старые строки и столбцы сохраняются.
Неизвестная несовместимая схема вызывает ошибку без удаления данных.
WAL и busy_timeout уменьшают конфликт записи. Резервную копию создавайте SQLite
backup API; одного копирования db-файла при работающем WAL недостаточно.

    python scripts/check_db_migration.py /absolute/path/to/credits.db

Скрипт читает исходник только для создания временной копии, дважды применяет
миграцию, сравнивает прежние строки и выполняет integrity_check.
Боевая база в этом аудите не открывалась.

    python -m compileall -q bot.py billing.py db.py texts.py assets.py scripts tests
    python -c "import bot, billing, db, texts, assets"
    python -m unittest discover -s tests -v
    python -m pip check

Тесты подменяют Telegram/ЮKassa и не списывают деньги.
CI выполняет проверки при push в main. Журнал и точка продолжения — AUDIT.md.

После обновления нужны проверка на отдельном тестовом боте/магазине, фактических
прав канала, preview на телефоне и настроек поддержки/урока.
Публикация в GitHub сама по себе не подтверждает обновление рабочего процесса:
конфигурации автоматического развёртывания в репозитории нет.

## Правила платформы

Telegram требует Stars для цифровых товаров/доступа, продаваемых внутри ботов;
наличие внешней платёжной страницы не отменяет это правило:
[официальное разъяснение](https://core.telegram.org/bots/payments-stars).
По явному запросу владельца существующая интеграция ЮKassa сохранена.
Этот аудит не подтверждает соответствие такой продажи правилам Telegram и
не меняет платёжного провайдера. Решение о модели продаж остаётся отдельным вопросом.

## Основа сценария

Приветствие объясняет следующий шаг, бесплатный материал доступен без анкеты,
после него — короткое описание пользы и прозрачные условия покупки.
Не добавлены выдуманные отзывы, гарантии результата или искусственные дедлайны.
Число уроков и наличие разборов сохранены из исходного проекта.
Использованы рекомендации [Manychat о приветствии](https://help.manychat.com/hc/en-us/articles/14281185974940-Welcome-Message-in-Manychat)
и [последовательной воронке](https://manychat.com/blog/lead-qualification-funnel/);
это сценарные принципы, а не обещание определённой конверсии.
