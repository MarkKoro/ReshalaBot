# Креативный мозг — ReshalaBot

Telegram-бот бесплатного урока и доступа к закрытому каналу. WebApp нет.
Рабочая схема разовой оплаты через ЮKassa сохранена: redirect, RUB, capture=true.
На экране разовой оплаты две прямые inline-кнопки: «Через СБП» и «Другие способы».
Первая использует payment_method_data.type=sbp и открывает отдельную страницу СБП:
QR-код на компьютере, выбор банка на телефоне. Вторая открывает Умный платёж
без payment_method_data/payment_method_id/payment_token: на странице доступны
все способы, подключённые в магазине. Настройки всего магазина не изменяются.
[СБП](https://yookassa.ru/developers/payment-acceptance/integration-scenarios/manual-integration/other/sbp),
[Умный платёж](https://yookassa.ru/developers/payment-acceptance/integration-scenarios/smart-payment).
Начальный тариф — 400 ₽ / 30 дней; администратор может менять тарифы из бота.
Оплата проверяется автоматически, затем бот сам присылает ссылку входа.
Автопродление добавлено как отдельная функция и **по умолчанию выключено**.

## Путь пользователя

1. /start присылает только приветствие. Существующая кнопка «▶️ Бесплатный урок»
   отправляет отдельное сообщение с видео/ссылкой только после нажатия.
2. Под уроком — переход к программе. Видео/ссылка сохраняется в истории отдельно.
   После перехода приветствие удаляется, а программа и дальнейшие шаги меняют одно
   сообщение под уроком. «Назад» возвращает к предыдущему разделу; возвращение к уроку
   не присылает ещё одну копию той же ссылки.
   /start заново отправляет только приветствие, чтобы восстановить экран даже после
   очистки переписки. Его кнопка повторно доставляет видео с превью; прежняя копия
   убирается только после успешной доставки. Название кнопки не меняется.
   Событие получения урока и отсчёт напоминания начинаются после доставки урока.
3. Программа → «Я хочу» → условия с ценой и сроком → «Через СБП» / «Другие способы».
   Обе кнопки сразу открывают соответствующую страницу ЮKassa; покупатель выбирает
   один вариант оплаты. Подсказка про «Ещё» удалена. При единственном тарифе отдельного
   экрана выбора нет. Если админ включит несколько вариантов, прямо под программой
   вместо «Я хочу» появятся inline-кнопки «Название · цена ₽», например
   «Три месяца · 990 ₽». Выбор ведёт сразу к условиям соответствующего тарифа.
4. После подтверждения ЮKassa бот сам отправляет приглашение. «Проверить оплату»
   — запасной способ, обязательного нажатия больше нет.
5. По ссылке человек подаёт заявку. Бот проверяет владельца ссылки и действующий
   доступ **до одобрения**. Пересланная ссылка не выдаёт доступ другому аккаунту.
6. /start действующего участника показывает срок, восстановление ссылки,
   продление и активность. Оставшиеся дни сохраняются при продлении.
7. Разовая подписка: одно уведомление за 3 дня до окончания и одно после
   подтверждённого исключения из канала. В обоих сразу полная цена и две прямые
   ссылки «Через СБП» / «Другие способы». Скидка игры повторно не применяется.

Выбор целей и примеры убраны по результатам проверки владельцем.
При одном тарифе в программе одна кнопка «Я хочу» и кнопка «Назад» к уроку.
Условия оплаты, готовый счёт, доступ и вспомогательные экраны также имеют возврат.
Inline-кнопка меняет сообщение, к которому она прикреплена, в том числе у старых
напоминаний. Урок остаётся отдельным материалом: его кнопка открывает меню под видео.
Новый экран сохраняется в SQLite; заменённое меню удаляется после успешной доставки.
Если Telegram запрещает удаление, бот пытается снять со старого меню кнопки.
Тайм-аут редактирования не создаёт дополнительное сообщение. Команды входа
(/start, /help, /terms, /admin) создают свежий экран внизу чата; переходы по кнопкам
дальше редактируют этот экран. Команда удаляется только после успешного ответа.
Приветствие и видео не объединяются в одно сообщение:
preview располагается под текстом урока. Внешний вид preview зависит от Telegram.
Bot API позволяет задать URL, размер медиа, позицию и включение превью, но не
текст описания YouTube-карточки или предел в две строки. Сохраняется большой
видеоплеер; prefer_small_media управляет размером медиа и не обрезает описание.
[Настройки превью Telegram](https://core.telegram.org/bots/api#linkpreviewoptions).

Команды покупателя: /start, /help, /support, /paysupport, /terms,
/cancel_subscription. Отмена автопродления сохраняет оплаченный срок.
Если платёж уже передан банку, отмена будущих попыток не отменяет его задним числом.

## Администрирование

### Instagram · n8n

Согласованные информационные страницы и порядок их размещения/обработки запросов
на удаление: [docs/instagram](docs/instagram/README.md).

`/admin` → **📸 Instagram · n8n**. Раздел доступен только настроенным администраторам
в личном чате; callbacks и текстовый ввод повторно проверяют ID администратора.
Кнопки позволяют включить/выключить автоответы, добавить или убрать ключевые слова,
заменить весь список, изменить ссылку, тексты и подписи кнопок. В режиме **Предпросмотр**
ничего не отправляется в Instagram. По умолчанию слово только **креатив**,
ссылка `https://t.me/BioMozg_agent`, отправка выключена до подключения Meta.

Охват — новые комментарии на любых старых и новых публикациях/Reels после включения.
Исторические комментарии задним числом не обрабатываются. Регистр и пунктуация не важны;
«некреативный» не запускает ответ. Лимит — один запуск человеку за 24 часа.
Первый Direct спрашивает, прислать ли ссылку; после ответа человека приходит сообщение
с кнопкой Telegram. Варианты текста выбираются устойчиво для конкретного человека.
Публичный ответ отправляется только после подтверждённой отправки Direct.
Стоп-слова и переписка человека с администратором приостанавливают автоматику для него.

Настройки сохраняются атомарно в `INSTAGRAM_CONFIG_PATH`, копия изменений и аудит —
в существующей таблице настроек бота. Этот JSON не содержит ключей или данных клиентов.
`INSTAGRAM_STATUS_PATH` показывает свежий статус обработчика; обычный вход в Instagram
не считается подключением API. При остановке n8n статус устаревает через 2 минуты.

Изолированный `instagram_gateway.py` проверяет подпись Meta и аккаунт @biomozg,
ведёт отдельную очередь/защиту от повторов. Никакого доступа к токену Telegram,
платежам или базе бота у его системного пользователя нет. Неопределённый результат
отправки, перезапуск во время отправки и ошибки Meta не вызывают слепую повторную рассылку.
В n8n `automation/instagram.n8n.json` запускает обработку каждые 15 секунд.
Отключение в Telegram применяется при следующей обработке и перед очередной отправкой;
уже переданный Meta запрос отменить задним числом нельзя.

Входящие сообщения и postback поддерживаются как в прежнем `entry.messaging`,
так и в `entry.changes` с полями `messages` / `messaging_postbacks` (Graph v26).
Оба формата используют одинаковые проверки согласия, окна и ID сообщения;
повторная доставка в другом формате не создаёт вторую отправку. События `standby`
не запускают ответы. В статусе есть только обезличенные счётчики `ingress_counts`,
без текста переписок и идентификаторов людей.

Для собственного System User включена резервная сверка Conversations API: только
диалоги, начатые этой кампанией за последние 24 часа, по одному за запуск n8n,
не чаще раза в 30 секунд для человека. Перед чтением проверяется, что именно
наше приложение владеет диалогом; управление у другого приложения не забирается.
При поиске читаются только ID/участники
не более 20 недавних диалогов; тексты читаются только после точного совпадения
обоих участников (не более 20 сообщений), затем ID диалога кешируется.
Реальные ID/время/ответы попадают в ту же очередь, что webhooks; повторная доставка
не дублирует ссылку. «Стоп» и ручной ответ, обнаруженные после согласия, блокируют
отправку ещё до обработки согласия. Неопределённая доставка требует ручной проверки
и не повторяется по новому ID согласия. Сверка не возобновляет старые рассылки.
В статусе `message_sync` показывает только счётчики и код ошибки, отдельно от
`last_webhook_at`. При малом числе диалогов резервный ответ обычно занимает до минуты;
при большой очереди задержка растёт. Новые права, сторонние подписки и AI не нужны.

Установка адаптера на этом сервере: `python3 scripts/install_instagram_service.py --apply`.
Она не перезапускает бота и не изменяет его БД. Затем штатно обновите/перезапустите
только `reshalo.service`. Секреты Meta находятся отдельно в
`/srv/biomozg-instagram/secrets/credentials.json` (0600), не в GitHub и не в Telegram:
`app_id`, `app_secret`, `ig_user_id`, `access_token`, `api_version`; сгенерированные
`verify_token` и `runner_token` сохраняются при обновлении. Не подставляйте тестовые
ключи и не включайте отправку до проверки аккаунта, подписок и реального теста.
В n8n импортируется заголовочный credential с runner_token и публикуется схема;
Meta получает callback `https://n8n.telegrambotsforeveryone.duckdns.org/instagram/webhook`.
Для собственного @biomozg используется **служебный пользователь своей компании**:
`api_mode=business_system_user`, хост `graph.facebook.com`. Нужны пять разрешений:
`instagram_basic`, `instagram_manage_comments`, `instagram_manage_messages`,
`pages_read_engagement`, `pages_show_list`. Два последних — зависимости подключения
через связанную Facebook-страницу; рекламные разрешения и публикация контента не нужны.
В credentials сохраняется ожидаемый `system_user_id` из `debug_token.user_id` —
это app-scoped ID, он отличается от ID пользователя, показанного в Business Suite.
Обработчик проверяет действительность токена, приложение, служебного пользователя,
разрешения, ID/имя Instagram и все три подписки. В v26 ответ `subscribed_apps`
содержит поля подписки без ID приложения; принадлежность ключа проверяется отдельно.

Для интеграции компаний-клиентов оставлен `api_mode=unified_login`: ожидаемый
`client_business_id` и @biomozg в `/me/assigned_instagram_accounts`. По требованиям
Facebook Login for Business портфолио приложения не должно совпадать с портфолио
компании-клиента. Этот путь не используется для подключения своего Instagram
в том же портфолио. У такого токена `/me` обозначает системного пользователя.
Для старого Instagram Login оставлена совместимость (`api_mode=instagram_login`
или отсутствие поля): `graph.instagram.com`, разрешения `instagram_business_basic`,
`instagram_business_manage_comments`, `instagram_business_manage_messages`.
Для всех вариантов нужны события `comments`, `messages`, `messaging_postbacks`.
Проверьте уровень доступа приложения: режим разработки может не обслуживать обычных
посетителей. Системный токен Unified Login может быть бессрочным, но его можно отозвать;
контроль подключения всё равно обязателен. Для старого Instagram Login долгоживущий
токен имеет срок действия; автоматическое продление пока не реализовано — перед
постоянным запуском с таким токеном требуется настроить обновление.

См. [служебные пользователи Meta](https://developers.facebook.com/docs/business-management-apis/system-users/install-apps-and-generate-tokens),
[требования Facebook Login for Business](https://developers.facebook.com/documentation/facebook-login/facebook-login-for-business)
и [начало работы Unified Login](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/get-started).

Официальные ограничения: [private replies](https://developers.facebook.com/documentation/instagram-platform/private-replies),
[quick replies](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/messaging-api/quick-replies),
[button template](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/messaging-api/button-template).

### Остальные настройки бота

/admin открывает кнопки; администратор также видит вход в меню на пользовательских
экранах. Все административные команды, callbacks и ввод проверяют Telegram ID и
доступны только в личном чате. Приоритет переменных: ADMIN_ID → ADMIN_IDS → ADMINS
(первая непустая, списки не объединяются). Пустая конфигурация не открывает доступ.

- **Лид-магнит:** установить любую публичную http/https ссылку, проверить порядок
  сообщений, удалить ссылку. Старые команды /set_intro_video и /clear_intro_video
  остаются aliases. Исторические media settings не удаляются.
- **Тарифы:** до 20 вариантов; название, целая цена 1–1 000 000 ₽, срок 1–3650 дней,
  включение/скрытие. Новый тариф сначала скрыт: после включения он добавится
  кнопкой с названием и ценой под описанием программы. При скрытии всех остальных
  вариантов снова останется «Я хочу». Уже выставленные счета сохраняют
  исходные цену и срок. Старые m1_first, m1, m3 продолжают обрабатываться.
- **Тексты:** приветствие, урок, программа, оформление, готовый счёт, вход,
  действующий доступ, продление, окончание, напоминание об уроке. До 2000 единиц
  длины Telegram; эмодзи могут занимать две. Поля {date}/{activity} проверяются;
  есть возврат исходного текста. Финансовые условия добавляются отдельно.
- **Настройки:** автопродление (выключено при первом запуске), мягкое напоминание
  об уроке, напоминание об окончании за 2–14 дней, ID группы, ссылка поддержки,
  ссылка на первый материал/навигацию внутри канала.
- **Выдать / отозвать доступ:** ID и срок для выдачи; ID для отзыва. При проблеме
  удаления участника админ получает ошибку и может повторить операцию.
  Отзыв отключает будущие автоплатежи. Настроенных администраторов бот не исключает.
- **Воронка / статистика:** первые запуски за 7/30 дней или всё время; достигнутые
  этапы и максимальный этап каждого человека; оплаты, выручка, источники,
  сообщения/медиа группы. Причины остановки и просмотры внешнего видео не угадываются.
- **Путь пользователя:** последние 25 событий, источник, активность, автопродление.
- **Проверить подключение:** права приглашения/удаления в канале, доступность группы,
  наличие настройки ключей. Проверка не создаёт платёж и не показывает секреты.

Ссылки, тексты и настройки сохраняются в SQLite, действуют после перезапуска и
не требуют публикации нового кода. Смена условий оферты по тому же URL требует
увеличения OFFER_VERSION в окружении; смена URL также требует нового согласия.

## Оплата и восстановление

В обычном разовом сценарии после «Я хочу» готовятся две ссылки для одного снимка
цены, срока и условий. Сначала создаётся счёт СБП, затем счёт Умного платежа.
Обе кнопки — URL-кнопки без дополнительного шага в боте. Создание счёта не списывает деньги.
Telegram не сообщает боту о нажатии URL-кнопок: показ условий не отмечается как
согласие. Снимок URL/версии оферты хранится со счётом, событие принятия записывается
для оплаченного счёта после подтверждённой покупки с пометкой payment_after_offer. Статистика не выдаёт
создание счёта за нажатие кнопки оплаты.
Если администратор отдельно включил автопродление, его явное согласие по-прежнему
собирается callback-кнопкой до создания запроса с сохранением способа оплаты.

Запрос создания счёта и его Idempotence-Key сохраняются **до** обращения к ЮKassa.
Счета одной пары связаны checkout_group_id. У каждого варианта свой неизменяемый
POST и ключ; повторный клик, тайм-аут и перезапуск используют исходные запросы.
SQLite допускает по одному открытому счёту каждого типа и только один неизвестный
запрос создания на пользователя. Второй вариант создаётся только после получения
ID первого; посторонние незавершённые счета блокируют новую пару. Неизвестный
второй POST восстанавливается фоновым заданием, а доступ по уже оплаченному первому
счёту выдаётся без задержки. При временной ошибке вместо отсутствующей URL-кнопки
показывается одноимённая кнопка повтора в том же меню.
Старые payload и ключи сохраняются; к известному разовому счёту можно подготовить
второй вариант с его прежними ценой, сроком и офертой. Изменения тарифов не меняют пару.
Проверка любой ссылки обнаруживает оплату через второй вариант; после подтверждения
меню заменяется на доступ. Неиспользованный счёт остаётся на сверке до отмены ЮKassa:
[API отменяет только waiting_for_capture](https://yookassa.ru/developers/payment-acceptance/getting-started/payment-process).
Если покупатель самостоятельно оплатит обе внешние страницы, обе покупки учитываются
и оплаченные сроки складываются, без потери денег или повторного учёта одного платежа.
Запросы с save_payment_method/payment_method_id не получают второго счёта;
согласованное автопродление и запрет новых списаний при неизвестном исходе сохраняются.

При сверке проверяются ID, владелец, проект, назначение, тариф, сохранённый срок,
сумма и RUB. Доступ выдаётся только для succeeded + paid=true.
waiting_for_capture не считается завершённой оплатой.
Срок берётся из сохранённого счёта, а не из текущих цен администратора.

Запись оплаты, продление, события и сохранённое согласие выполняются в одной
транзакции BEGIN IMMEDIATE. Повторная обработка не добавляет второй срок.
Общая SQLite connection сериализована; операции одного пользователя защищены
блокировкой. Запускать **один процесс polling на токен и базу**.

Фоновая сверка запускается каждые 20 секунд, выдача оплаченного доступа —
автоматически, без публичного webhook-сервера. Сетевые ошибки и очередь могут
увеличить задержку. Подтверждённая оплата сохраняется даже при ошибке Telegram;
неудачная доставка повторяется отдельно с паузой 5 минут, без повторного продления.
При неопределённом ответе Telegram возможен повтор сообщения, но не повтор оплаты.
Уже завершённые исторические платежи при миграции повторно не рассылаются.

ЮKassa гарантирует идемпотентность в течение 24 часов:
[документация API](https://yookassa.ru/developers/using-api/interaction-format).
Поэтому неизвестный POST без payment_id старше 23 часов автоматически не повторяется.
Такой редкий случай требует сверки оператором в ЮKassa; нельзя удалять запись
или создавать новый платёж наугад. Счета с известным ID продолжают проверяться GET.

## Игра в напоминании об уроке

Единственное напоминание через 22–24 часа после выдачи урока содержит вопрос:
«Какое понятие в уроке называют фундаментальным и редко меняют?» и ровно три
кнопки: «Форма», «Функция», «Правило». Сам вопрос не создаёт платёж.

- «Правило»: поздравление, скидка 30% и итоговая цена. Для тарифа 400 ₽ — 280 ₽.
- «Форма» / «Функция»: объяснение правильного ответа, повтор видео в этом же
  сообщении и утешительная скидка 15%. Для тарифа 400 ₽ — 340 ₽.

После ответа сообщение редактируется, под ним только «Через СБП» и «Другие
способы». Нет кнопок возврата, проверки, оферты или админки; URL условий находится
в самом тексте перед оплатой. СБП — отдельная страница СБП, второй вариант —
все подключённые способы ЮKassa. Оба счёта содержат действительную сумму со скидкой.
Цена считается в целых копейках; при исходных 999 ₽ скидка 30% даёт 699,30 ₽.

Первый ответ, процент, исходная цена, срок, URL/версия условий и связь с парой
счетов сохраняются в lesson_quizzes. Другой ответ, двойной клик, перезапуск и
изменение администратором тарифа не пересчитывают результат. Скидка относится
к этой первой покупке; последующие покупки и автопродление используют обычные
правила. Если опубликовано несколько тарифов, используется выбранный человеком
либо creative_30; если его нет — первый доступный по сроку тариф. Для игры нужен
тариф не дешевле 2 ₽, настроенные урок и условия оплаты.

При переходе с известного неоплаченного разового счёта без скидки создаётся
новый запрос с новым ключом, а прежний checkout помечается superseded локально.
Старые платежи, payload и ключи не меняются и остаются на сверке ЮKassa; отмена
pending не имитируется. Неизвестный исход запроса или проверки блокирует новые
счета до безопасного восстановления. Автопродление не подключается через игру.

Повторных напоминаний об уроке после приглашения в игру нет, даже если человек
ничего не ответил или не оплатил. Восстановление неизвестного запроса также не
рассылает дополнительных сообщений «счёт готов». Подтверждение оплаты и выдача
оплаченного доступа сохраняются. Ранее отправленные обычные напоминания повторно
не рассылаются ради новой игры.

## Автопродление — отдельная опция

Обычные покупки не сохраняют способ оплаты. Существующие участники не подключаются
к автопродлению автоматически. Чтобы предлагать его новым покупателям, администратор
должен отдельно включить опцию в настройках; покупатель затем выбирает явную кнопку
с согласием на цену, срок и повторное списание.

Две предварительные оплаты не требуются: способ можно сохранить при первой
успешной покупке. Доступность зависит от магазина и способа оплаты; требуется
payment_method.saved=true. Без подтверждения сохранения автопродление не включается.
[ЮKassa: подключение автоплатежей](https://yookassa.ru/docs/support/payments/extra/autopayment),
[оплата сохранённым способом](https://yookassa.ru/developers/payment-acceptance/scenario-extensions/recurring-payments/pay-with-saved).

- Опция доступна для тарифов от 3 дней. Сохраняются цена, срок и согласие покупателя.
- За настроенное число дней до окончания приходит предупреждение с ценой,
  сроком и отменой. Попытка списания — за сутки до окончания и не раньше 12 часов
  после подтверждённой отправки предупреждения.
- На один период допускается один счёт. Ручной или неизвестный платёж блокирует
  новое автоматическое списание.
- Подтверждённый отказ останавливает автоматические попытки и даёт кнопку ручного
  продления. Тайм-аут сначала сверяется: он не означает отказ банка.
- Изменение цены/срока или скрытие тарифа приостанавливает продление до нового выбора.
- /cancel_subscription доступна в любое время. Поздний ответ первого платежа
  не может снова включить уже отменённое согласие.
- При недоставленном предупреждении списания нет. Просроченные пропущенные периоды
  не догоняются серией списаний. После окончания доступа автопродление отключается.

Подключение рекуррентных платежей конкретного магазина в этом аудите не проверялось.
Чеки, договор магазина, возвраты и споры обслуживаются в существующей настройке
ЮKassa. Возврат в кабинете не вызывает автоматического отзыва доступа: администратор
должен отдельно использовать «Отозвать доступ». Автоматизация возвратов не добавлялась.

## Доступ, группа и напоминания

Приглашение действует час, использует creates_join_request. Боту нужны права
can_invite_users и can_restrict_members. На вход проверяются пользователь, срок
подписки и ссылка; после одобрения ссылка отзывается. Если настроена ссылка первого
урока, новому участнику приходит короткий следующий шаг.

Старые ссылки прежнего формата обрабатываются обработчиком вступления.
После окончания и ручного отзыва открытые ссылки отзываются, участник блокируется;
перед новым подтверждённым доступом снимается блокировка. При ошибке прав
истечение повторяется; покупателю не сообщается об успешном удалении до результата.
После banChatMember бот проверяет getChatMember: требуется статус kicked/left.
Блокировка сохраняется до новой подтверждённой покупки/выдачи доступа.
[Telegram: исключение участника](https://core.telegram.org/bots/api#banchatmember),
[проверка участия](https://core.telegram.org/bots/api#getchatmember).

Для разовых подписок приходит одно уведомление за reminder_days (по умолчанию 3)
дня и второе сразу после подтверждённого исключения. Первое задание проверяет
сроки каждые 5 минут, исключение и второе уведомление — каждую минуту.
Оба сообщения появляются внизу чата, содержат полную опубликованную цену/срок,
условия и готовые URL-кнопки «Через СБП» / «Другие способы». Дополнительных
переходов для выставления счёта нет. Продление использует текущий тариф прошлой
покупки; если он скрыт, первый доступный тариф по сроку. Скидка 15%/30% действует
только для первой покупки: её неиспользованный вариант больше не предлагается.

Новая пара для продления хранит purpose=subscription_renewal и subscription_until
в metadata, без quiz_token/discount_percent. Цена берётся из tariffs, не из суммы
прошлой покупки. Запросы/ключи прежних счетов не переписываются; известные
неоплаченные ручные варианты локально помечаются superseded и остаются на сверке.
Счета с неопределённым исходом нельзя заменять. Если ссылки из первого уведомления
отменены ЮKassa, ко второму создаётся новая пара по полной цене. Подготовка ссылок
не списывает деньги и не подключает автопродление.

Перед исключением сверяются начатые платежи обоих способов. Подтверждённая покупка
продлевает доступ до исключения; известный неоплаченный pending не даёт отсрочки.
Только неизвестному исходу или waiting_for_capture даётся максимум 24 часа
отсрочки, затем доступ закрывается. Поздний подтверждённый платёж обрабатывается
и восстанавливает оплаченный срок.

Окончание доступа и доставка уведомления сохраняются отдельно. При сбое подготовки
ссылок после исключения бот повторяет подготовку/отправку с теми же ключами,
без повторного исключения. До готовности обеих ссылок попытка доставки не считается
начатой. Перед Telegram сохраняется ключ уведомления с датой окончания подписки,
чтобы повторный запуск задания или перезапуск не дублировал его. При неопределённом
ответе Telegram повторной рассылки нет. Старые отмеченные уведомления не рассылаются
заново. После покупки маркетинговые напоминания об уроке и игре не отправляются.

Отдельно включённое и явно согласованное автопродление сохраняет прежнее
предупреждение с ценой и отменой: ручная пара не создаётся одновременно со списанием.
На проверенном сервере опция выключена, активных согласий нет.

Учёт активности работает только в указанной группе для действующих участников:
сообщения и сообщения с файлами/медиа. Повторное событие не увеличивает счётчик;
редактирования, сообщения ботов и анонимных отправителей не учитываются.
Содержимое сообщений, имена файлов и файлы не сохраняются. Один медиапост считается
одним сообщением с медиа. Фотоальбом может состоять из нескольких сообщений.
Telegram не даёт боту историю сообщений до подключения.
Для получения всех новых сообщений добавьте бота администратором группы либо
настройте режим приватности в BotFather.
[Ограничения Bot API](https://core.telegram.org/bots/api).

Персональное напоминание использует только ненулевые счётчики за последние 30 дней.
«Разборы» автоматически не распознаются. Через 22–24 часа после первой отправки
лид-магнита возможна одна мягкая попытка напоминания: без оплаты/активного доступа,
без неизвестных счетов и при отсутствии отказа от таких сообщений.
Эту рассылку можно отключить в админке; прежние отказы пользователя учитываются.
Напоминание с игрой становится текущим меню внизу чата: три ответа меняют именно
его на результат с оплатой, а предыдущее меню убирается. Урок при этом сохраняется.
При неопределённой доставке маркетинговое сообщение повторно не отправляется.

Источники: https://t.me/BOT_USERNAME?start=instagram_creative и аналогичные
параметры из латинских букв, цифр, _ и - (до 64 символов).
Воронка группирует по **первому** запуску, повторные старты не создают новых людей.
Ссылка урока означает отправку, а не просмотр видео.

## Запуск, база и проверки

Python 3.10+; локальные проверки: Python 3.12, python-telegram-bot 21.11.1,
aiosqlite 0.21.0, httpx 0.28.1, python-dotenv 1.2.2.
Существующий список зависимостей сохранён. Команды:

    python -m pip install -r requirements.txt
    python bot.py

Заполните прежнее окружение по .env.example; не заменяйте рабочие ключи тестовыми.
DB_PATH должен указывать на прежний постоянный SQLite-файл. Относительный путь
отсчитывается от рабочего каталога процесса; без переменной используется
credits.db рядом с db.py. Настройки в базе имеют приоритет над начальным заполнением env.
Не запускайте два процесса бота одновременно.

Миграция добавляет таблицы тарифов, запросов платежей, согласий, доставки,
активности и аудита настроек; старые строки и столбцы сохраняются.
Для независимого хранения урока добавляются users.lesson_chat_id,
lesson_message_id и lesson_url. Эти поля не заменяют координаты текущего меню.
Неизвестная несовместимая схема вызывает ошибку без удаления данных.
WAL и busy_timeout уменьшают конфликт записи. Резервную копию создавайте SQLite
backup API; одного копирования db-файла при работающем WAL недостаточно.

    python scripts/check_db_migration.py /absolute/path/to/credits.db

Скрипт читает исходник только для создания временной копии, дважды применяет
миграцию, сравнивает прежние строки и выполняет integrity_check.
Исходная база скриптом не изменяется.

    python -m compileall -q bot.py billing.py db.py texts.py assets.py scripts tests
    python -c "import bot, billing, db, texts, assets"
    python -m unittest discover -s tests -v
    python -m pip check

Тесты подменяют Telegram/ЮKassa и не списывают деньги.
CI выполняет проверки при push в main. Журнал и точка продолжения — AUDIT.md.

После обновления нужны проверка на отдельном тестовом боте/магазине, фактических
прав канала, preview на телефоне и настроек поддержки/урока.
Публикация в GitHub сама по себе не подтверждает обновление рабочего процесса:
конфигурации автоматического развёртывания в репозитории нет.

## Правила платформы

Telegram требует Stars для цифровых товаров/доступа, продаваемых внутри ботов;
наличие внешней платёжной страницы не отменяет это правило:
[официальное разъяснение](https://core.telegram.org/bots/payments-stars).
По явному запросу владельца существующая интеграция ЮKassa сохранена.
Этот аудит не подтверждает соответствие такой продажи правилам Telegram и
не меняет платёжного провайдера. Решение о модели продаж остаётся отдельным вопросом.
