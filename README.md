# Креативный мозг

Telegram-бот доступа к закрытому каналу: **400 ₽ за 30 дней**, ручное продление.
Используются прежние Python, python-telegram-bot, httpx/YooKassa, aiosqlite/SQLite
и JobQueue. API YooKassa не менялся. Рекуррентных списаний и сохранения способа
оплаты нет. Продление добавляет 30 дней к действующему сроку, новая покупка после
окончания — к моменту подтверждения.

## Пользовательская воронка

1. `/start` сразу отправляет приветствие и YouTube-ссылку с preview, без оферты.
2. Кнопка под уроком открывает один экран продукта.
3. «Поехали →» показывает оферту, если актуальная версия ещё не принята.
4. Принятие оферты сразу создаёт счёт. При уже принятой оферте счёт создаётся сразу.
5. YooKassa → «Проверить оплату» → персональная URL-кнопка входа.

Экран продукта — короткое приглашение с пользой курса и разборов.
Цена показана только на финальной кнопке «💳 Оплатить 400 ₽», после оферты;
текст этого экрана сообщает срок 30 дней и способ получения ссылки.
Перед оплатой также явно указано отсутствие автоматических списаний.

Лид-магнит отправляется отдельным сообщением, не включается в механизм
редактирования/удаления текущего экрана и остаётся в истории. Первый `/start`
использует приветствие из ТЗ; повторное получение кнопкой «Бесплатный урок» —
короткий caption. Под каждым сообщением одна кнопка продукта.

Активному подписчику `/start` показывает срок и прямую кнопку продления.
За 3 дня до окончания приходит напоминание. Фоновые задачи проверяют состояние
каждый час; удаление из канала происходит при следующем запуске задачи после
окончания срока. При ошибке прав/сети удаление повторяется в следующем запуске.
Уведомления отправляются новыми сообщениями, чтобы Telegram действительно уведомил
получателя, а не просто отредактировал старый экран.

## Запуск и окружение

В репозитории на момент изменения не было README, .env.example, Dockerfile,
Procfile, systemd/hosting-конфигурации или deployment workflow.
Существующий процесс запуска на сервере менять не требуется: `python bot.py`.
Python 3.10+; проверки выполнены на Python 3.12 и PTB 22.8.
Список зависимостей оставлен прежним, их версии в исходном репозитории не закреплены.
Версия Telegram-библиотеки на рабочем сервере недоступна для проверки; принудительного
обновления не требуется. Для PTB до 20.8 предусмотрен обычный link preview.

```sh
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
cp .env.example .env
# Заполнить .env или переменные процесса, затем:
python bot.py
```

Один polling-процесс на BOT_TOKEN и одну БД. Путь к БД должен указывать на
постоянный диск/volume, доступный на запись. При обновлении не удаляйте БД.
Если `DB_PATH` не задан, сохраняется прежний путь `credits.db` рядом с `db.py`.
Относительный путь из env вычисляется относительно рабочего каталога процесса;
на сервере предпочтителен прежний абсолютный путь.

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Секрет токена Telegram-бота |
| `YOOKASSA_SHOP_ID` | ID текущего магазина |
| `YOOKASSA_SECRET_KEY` | Секретный ключ текущего магазина |
| `CHANNEL_ID` | Единственный источник ID закрытого канала для invite, ban/unban и revoke |
| `PROJECT_KEY` | `creative_brain` для новых счетов; env переопределяет default |
| `ADMIN_ID` | Основной числовой Telegram user ID администратора, имеет приоритет |
| `ADMIN_IDS` | Совместимость: список ID через запятую/пробел, только если `ADMIN_ID` пуст; затем fallback на `ADMINS` |
| `OFFER_URL` | Начальная оферта, только если `settings.offer_url` ещё отсутствует |
| `OFFER_VERSION` | Версия условий, default `1`; меняйте при обновлении текста по тому же URL |
| `BOT_USERNAME` | Имя без @ для возврата в бот |
| `YOOKASSA_RETURN_URL` | Имеющийся URL возврата имеет приоритет и сохраняет прежнее поведение |
| `DB_PATH` | Прежний SQLite-файл |
| `FOLLOWUP_ENABLED` | `true`/ `false`; изменение применяется после перезапуска |

Секретов и фактического deployment environment в репозитории нет.
Если в серверном env явно задан прежний `PROJECT_KEY`, **измените его на
`creative_brain`**: изменение default в Python не переопределит env.
Не переименовывайте репозиторий, канал или бот автоматически из-за смены
внутреннего project key.

## Лид-магнит и админка

Администратор из окружения открывает личный чат:

1. `/admin` → **🎬 Лид-магнит**.
2. **🔗 Установить / заменить ссылку** → отправить ссылку на видео
   `https://www.youtube.com/watch?v=VIDEO_ID` либо `https://youtu.be/VIDEO_ID`.
   Также принимаются мобильные, Shorts, live и embed URL YouTube.
3. **👀 Проверить как пользователь** — бот отправляет себе настоящий preview.
   Тестовая отправка не создаёт `lead_magnet_sent` и не запускает follow-up.
4. **🗑 Удалить ссылку** удаляет настройку, но не историю сообщений и не старое видео.

Ссылка хранится в `settings.lead_magnet_url`. Меняется без redeploy.
Проверяются http/https, точный домен YouTube и формат ID видео.
Публичность и доступность самого видео нужно проверить вручную.
Telegram получает `LinkPreviewOptions(prefer_large_media=True, show_above_text=True)`;
при отсутствии поддержки используется обычный preview. Итоговая миниатюра и способ
воспроизведения зависят от Telegram-клиента и доступности YouTube.
См. [документацию PTB](https://docs.python-telegram-bot.org/en/stable/telegram.linkpreviewoptions.html).

В приоритет взято явное изменение ТЗ «лид-магнит хранится на YouTube».
Загрузка direct video, Telegram file_id и source message/channel для новой воронки
не используются; дополнительный env для source-channel не нужен.
`intro_video_file_id` и `review_photos` остаются в SQLite ради совместимости.

Команды:

- `/set_lead_magnet`, `/clear_lead_magnet`.
- `/set_intro_video`, `/clear_intro_video` — временные aliases управления **YouTube URL**.
- `/set_offer` — изменить оферту. Старая запись принятия сохраняется, но перед новой
  покупкой потребуется согласие с условиями нового продукта. Смена URL или
  `OFFER_VERSION` также требует нового согласия. Уже оплаченный счёт можно проверить
  без повторного согласия.
- `/grant` → ID и положительное количество дней; `/revoke` → ID.
- `/stats` — воронка и общая статистика.
- `/user_path` — последние 25 событий указанного Telegram ID.

Раздел отзывов, быстрые кнопки добавления фото и старые команды отзывов удалены.
Обычные сообщения пользователя не удаляются; cleanup сохранён для вводов админа.

На пользовательских экранах администратора есть отдельная inline-кнопка
**⚙️ Админ-меню**; в разделах админки — кнопка возврата. Она доступна и под
уроком, при отсутствии урока, в оплате, статусе доступа и уведомлениях.
Переход в меню очищает незавершённый ввод администратора.
Обычным пользователям эта кнопка не добавляется. Они могут набрать `/admin`,
но команда, admin callbacks и ручной ввод проверяют фактический Telegram user ID
отправителя и не открывают им меню, статистику или изменение настроек/доступа.
Админские операции разрешены только в личном чате.

Выбирается первая непустая переменная: `ADMIN_ID` → `ADMIN_IDS` → `ADMINS`.
Списки не объединяются, чтобы старое значение не выдало лишние права.
Пустая конфигурация либо некорректный основной ID не открывают админку всем;
если в выбранной переменной нет положительных числовых ID, доступ закрыт.
После изменения env перезапустите процесс бота.

## Платежи и совместимость

Новые счета создаются только для `creative_30`: `400.00 RUB`, 30 дней.
Архивные `m1_first`, `m1`, `m3` доступны только при проверке уже записанного счёта:
сохраняются его исходные сумма и срок. Старые кнопки выбора тарифа открывают
актуальный продукт и не создают архивных счетов.

Проверяются payment ID, владелец, исходные metadata, сумма, RUB и финальный статус
`succeeded` с `paid=true`. Одного `paid=true` в `waiting_for_capture` недостаточно.
Исходный project key берётся из локальной записи счёта и сверяется с YooKassa:
поэтому незавершённые счета переживают смену бренда и env.
Metadata старого счёта не перезаписываются ответом провайдера.

`finalize_payment_once` сохраняет доступ и события оплаты в одной транзакции
`BEGIN IMMEDIATE`. Повторная проверка не добавляет ещё один срок и не удваивает
выручку. Операции общей SQLite connection сериализованы, чтобы commit фоновой
задачи не разрывал транзакцию. Операции покупки, удаления и follow-up одного
пользователя также разделены блокировкой.

При повторном Buy в течение суток используется последний незавершённый новый счёт,
если он не отменён. Для нового POST сохраняется прежняя схема: случайный UUID
в заголовке Idempotence-Key.
Автоматическая проверка всех счетов как отдельный сервис не добавлена:
основной способ подтверждения — кнопка проверки.

Invite создаётся в `CHANNEL_ID`, `member_limit=1`, сроком на час.
Событие вступления отзывает ссылку, поскольку member_limit ограничивает количество
одновременных участников, а не суммарное число использований.
Чужой пользователь, вошедший по персональной ссылке, удаляется.
При повторной проверке истёкшая ссылка заменяется без продления подписки.
При expiration/revoke открытые ссылки пользователя отзываются.
См. [Telegram Bot API](https://core.telegram.org/bots/api#createchatinvitelink).

Если оплата прошла, а Telegram не выдал ссылку, срок уже сохранён: можно повторить
проверку оплаты после исправления прав. Не выдавайте ещё 30 дней вручную вместо
повторной проверки, если это не намеренное продление.

## Follow-up и аналитика

Через 22–24 часа после **первой** отправки урока бот делает максимум одну попытку
отправить мягкий follow-up. Условия: нет успешных платежей за всю историю,
нет активной подписки и нет предыдущей попытки. Перед отправкой проверяются
незавершённые счета YooKassa — даже если человек оплатил, но не нажал «Проверить».
При недоступности проверки платёжного статуса сообщение не отправляется.

Попытка фиксируется до Telegram-запроса и переживает перезапуск. При timeout
повторной отправки нет: иначе нельзя исключить дубликат. Поэтому возможна
неподтверждённая/пропущенная доставка. Если бот был выключен всё окно 22–24 часа,
запоздалый follow-up не отправляется. `FOLLOWUP_ENABLED=false` отключает задачу.

Deep links: `https://t.me/<BOT_USERNAME>?start=instagram_creative`,
`youtube_creative`, `telegram_creative`, `reels_creative`, `shorts_creative`.
Без аргумента источник `direct`. Допустимы 1–64 латинских буквы, цифры, `_`, `-`.
Первый источник хранится в `users.first_source`, последующие Start также
пишутся событиями с фактическим параметром.

События: `start`, `lead_magnet_sent`, `product_opened`, `buy_clicked`,
`offer_accepted`, `payment_created`, `payment_succeeded`, `access_granted`,
`followup_sent`, `renewal_started`, `expired`.
Отправка ссылки не означает просмотра видео; событие просмотра не создаётся.

В статистике Start показан как число вызовов и уникальных людей; этапы воронки —
уникальные люди, рядом число счетов/оплат. Конверсии считаются по людям с
соответствующим событием входа и последующей успешной оплатой новой воронки,
поэтому повторные Start и продления не раздувают процент.
Общие оплаты/выручка включают старые финализированные платежи.
Start/Paid по source — уникальные люди с первым источником; `unknown` означает
исторического пользователя без записанного источника.

## Миграция SQLite

При запуске добавляются:

- `funnel_events`, два индекса по событию/пользователю/времени и уникальный ключ
  для идемпотентных событий оплаты.
- `followup_deliveries`: ID пользователя, время попытки, время успешной отправки.
- `users.first_source`, `accepted_offer_url`, `accepted_offer_version`.
- Прежние поля уведомлений в subscriptions, если их ещё нет.

Записи существующих таблиц и старые media settings сохраняются.
Опасная прежняя логика удаления несовместимых таблиц заменена проверкой:
при неизвестной схеме запуск останавливается с ошибкой **без удаления данных**.
Такую базу нужно мигрировать отдельно после изучения её схемы.

Перед обновлением сохраните резервную копию SQLite штатным backup API, особенно
если используются WAL-файлы. Для проверки реального файла на копии:

```sh
python scripts/check_db_migration.py /absolute/path/to/credits.db
```

Скрипт открывает исходник read-only, создаёт временную копию через SQLite backup,
дважды применяет миграцию, сравнивает все прежние поля всех строк и выполняет
`PRAGMA integrity_check`. Исходный файл не изменяется.
Боевая БД не предоставлялась; автоматические тесты используют копию базы,
созданной по точной схеме предыдущей версии и заполненной контрольными записями.

## Проверка перед рабочим запуском

1. Владелец канала должен добавить бота администратором с правами приглашать
   пользователей и блокировать/удалять участников. Проверить фактический
   `CHANNEL_ID`, закрытость канала, закреплённое сообщение и Урок 1.
2. В BotFather вручную заменить имя/описание/аватар продукта, при необходимости
   изменить название/оформление канала и обновить текст существующей оферты.
   Код не меняет эти внешние настройки.
3. Для теста используйте отдельного бота, закрытый тестовый канал, отдельный
   `DB_PATH` и тестовый магазин YooKassa с его ключами. Не подключайте тестовый
   процесс к боевому BOT_TOKEN, каналу или SQLite-файлу.
4. Установите оферту и YouTube URL через admin. Проверьте preview на телефоне.
5. С обычного тестового аккаунта пройдите Start → продукт → оферта → счёт.
   Проверьте `400.00 RUB` и описание; оплатите тестовыми данными из
   [инструкции YooKassa](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing).
   Вернитесь в бот и нажмите «Проверить оплату».
6. Откройте URL-кнопку входа, проверьте канал и доступ на 30 дней. Повторите
   проверку этого счёта: дата должна остаться прежней. Купите новый период —
   добавятся ровно 30 дней.
7. Проверьте `/grant` и `/revoke` на тестовом аккаунте, `/stats` и `/user_path`.
   Проверьте expiration/напоминание в отдельной тестовой БД с укороченными датами
   и вызовом job; не меняйте ради этого рабочие сроки.
8. Запустите автоматические проверки:

```sh
python -m compileall -q bot.py db.py texts.py assets.py scripts tests
python -c "import bot, db, texts, assets"
python -m unittest discover -s tests -v
python -m pip check
```

Тесты не обращаются к настоящим Telegram/YooKassa и не списывают деньги.
Они покрывают callbacks, миграцию/сохранение записей, новую покупку, старые счета,
продление, идемпотентность, invite/права, grant/revoke, expiration, уведомления,
preview/fallback, источники, конверсии и единственность follow-up.
